AEC ARTS PRIVATE SHARED WORKSPACE — DEPLOYMENT CHECKLIST
========================================================

The package has been consolidated against the existing private GitHub repository and the existing D1 database `aec-arts-private-catalogue`.

BEFORE DEPLOYMENT
- Keep the folder layout intact: index.html, 0001_private_catalogue.sql, worker.test.mjs, AEC_Arts_Shop_v10_Image_Zoom_Tagline.html.
- wrangler.toml already contains the existing D1 database ID. Do not change it or use Mon-Gen's database.
- Do not deploy the public customer shop or attach its domain.

CLOUDFLARE
1. Connect the private GitHub repository to a NEW Worker called `aec-arts-private-workspace` under Workers & Pages / Workers Builds.
2. Set Worker secrets: AEC_OWNER_PASSWORD, AEC_PARTNER_PASSWORD, AEC_SESSION_SECRET. Use two different strong passwords and a separate long random session secret. Never commit these values.
3. Use `npm run deploy` as the deploy command in a standard Node/npm build environment. The script first applies migrations to `aec-arts-private-catalogue`, then runs `wrangler deploy`.
4. Stop if the deployment screen shows an error; keep the full error text and fix the actual cause before retrying.

LIVE VERIFICATION — REQUIRED
- Worker deployment succeeds and assigned HTTPS page loads.
- Wrong password is rejected.
- Owner and partner can sign in on separate browsers/devices.
- A test product saved on one device appears on the other after refresh.
- An edit syncs back; stale edits are blocked instead of overwriting changes.
- Sign-out clears access.
- Delete the test product.
- Export and back up the existing catalogue before importing. Import only after two-device tests pass; import replaces the shared catalogue.

This is a private catalogue manager only. It does not launch the public shop or enable real checkout. Local tests passed, but live verification is still outstanding.
